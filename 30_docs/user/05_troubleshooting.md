# MDHのトラブルシューティング

## 処理結果を確認する

- `daily` の「対象ファイルに変更なし」は表示された日報の保存判定です。隣接日報の更新に失敗した場合、対象日報は保存済みの可能性があります。表示された日付とファイルを確認してください。
- `todo` が転記を保留した場合は、チェックが残ります。警告に該当する日報や `## done` を確認して再実行してください。
- `md-db` の操作結果と終了コードを確認します。部分成功・保留の詳細は応答の `diagnostics` または `-Verbose` で確認できます。

## よくあるエラーと対処

| 表示・状況 | 確認・対処 |
|---|---|
| 日付形式エラー | `yyyy-MM-dd` 形式で指定し、暦上実在する日付か確認 |
| 前の日報がない警告 | 指定基準日より前に、規定の保存場所・ファイル名の日報があるか確認 |
| `config.paths.daily` 未初期化、日報ルート不在 | 起動スクリプトを読み込めているか、`paths.daily` とディレクトリを確認 |
| 日報テンプレートが見つからない | `daily.template` が実在する `DailyTemplate.md` を指すか確認 |
| テンプレートの必須要素エラー | テンプレートに4つの必須プレースホルダーと予定見出し・マーカーがあるか確認。テンプレートの仕様を参照 |
| 予定取得未実装の警告 | 現行実装では予定取得できないため、予定は手入力する |
| 予定領域が一意でない警告 | 予定見出し・開始終了マーカーが重複していないか確認。手入力は自動管理領域の外に置く |
| 読込エラー | 日報ファイルが他のプロセスでロックされていないか、UTF-8 として読めるか確認 |
| 読込後に変更されたため上書き中止 | 他の編集を保持するための保護動作。最新ファイルを再読込し、内容を確認してからコマンドを再実行 |
| todo実行時に日報がない警告 | 完了チェックを保持する保護動作。`daily` で日報を作成してから `todo` を再実行 |
| ルーティンファイルがない警告 | `todo.routine_file` が実在するMarkdownファイルを指すか確認 |
| 完了タスクを記録しない警告 | 最新日報が新形式で、`# 🤖 自動入力` と配下の `## done` が一意か確認。旧履歴との競合が報告されたら日報とTODOを照合する |
| ファイルを開けない | 保存自体が成功しているか確認し、`code` コマンドまたは OS の既定アプリを確認 |

## DBと集約の復旧

DBは日報Markdownから再生成できます。DBの状態が異常なときは、まず `md-db -Status` と診断を確認してください。破損したポインターや日報ルートの不一致を報告された場合は、既存ストアを保全し、障害対応と別ストアでの復旧手順に従います。

集約が日報の解析で失敗した場合は、表示された日報パスと解析理由を確認してください。手入力ファイルへの上書きが拒否された場合、exportなら別の `-OutputPath` を指定できます。診断や部分失敗時の動作は[集約コマンド](04_commands.md#mdreverse-と-mdrun)を参照してください。

## インストーラーが停止したとき

- `要修正で停止` の場合は、表示された段階とパスを確認してから `-WhatIf` を再実行します。別のMDHへの登録、別スクリプト経由の読み込み、壊れた管理マーカーは手動で確認します。リンクを経由する保存先も、表示されたパスを確認してください。
- `一部適用` の場合は、表示された適用済み項目を保持します。プロファイルを排他的に開けなければ、編集や同期が終わってから再実行します。
- 既存プロファイルを変更するとき、隣に `<プロファイル名>.mdh-<識別子>.bak` が作られます。復旧時は現在のプロファイルと退避ファイルを比較し、後から追加された設定があれば保持したうえで管理ブロックを手動で取り除きます。追加編集がないと確認できた場合は、エディターを閉じて退避ファイルから元のパスへ復元できます。
- Pythonの診断に失敗した場合は、表示された実行ファイルと製品用の依存設定を確認します。`code` がない環境では `mdstart -NoOpen` でファイル表示を省略できます。
